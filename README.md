## เริ่มใช้งาน

> ✅ **ตั้งค่าเสร็จแล้ว (3 ก.ย. 2026)** — Sheet + Apps Script + Deploy + `GAS_URL` เรียบร้อย
> เว็บอ่านข้อมูล 40 โต๊ะจาก Google Sheet ได้จริงแล้ว เหลือแค่ใส่รายชื่อแขก
> ขั้นตอนด้านล่างเก็บไว้เผื่อต้อง deploy ใหม่หรือย้ายเครื่อง

**1. ตั้งค่า backend** → ทำตาม [`gas/README.md`](gas/README.md) (ประมาณ 10 นาที)

**2. ใส่ค่าใน [`js/core.js`](js/core.js)**

```js
const CONFIG = {
  GAS_URL: 'https://script.google.com/macros/s/…/exec',

  couple: {
    groom: { name: 'สุทิวัส กำเนิดว้ำ',      nick: 'หนึ่ง' },
    bride: { name: 'ณัฐฐาพร อินทรสวัสดิ์', nick: 'อาย' }
  },
```

**3. ทดสอบในเครื่อง** — เปิดผ่าน server เท่านั้น (เปิดไฟล์ตรง ๆ service worker จะไม่ทำงาน)

```bash
cd wedding-seating
python -m http.server 8000
# เปิด http://localhost:8000
```

**4. ขึ้นออนไลน์** — GitHub Pages ฟรีและพอเหลือเฟือสำหรับ 400 คน
ต้องเป็น **https** เท่านั้น ไม่งั้น service worker และปุ่มคัดลอกลิงก์จะไม่ทำงาน

## ฟีเจอร์

### หน้าแขก
- **ค้นหาแบบยืดหยุ่น** — สะกดผิด สระหาย ไ/ใ สลับ คำนำหน้าไม่ตรง ก็ยังหาเจอ
- ค้นได้ด้วย ชื่อจริง · นามสกุล · ชื่อเล่น · ชื่อกลุ่ม (พิมพ์ `HONDA` ขึ้นทั้งกลุ่ม) · เลขโต๊ะ
- **โหมดจิ้มอย่างเดียว ไม่ต้องพิมพ์** — กดฝั่งเจ้าบ่าว/เจ้าสาว → เห็นโต๊ะทั้งหมดของฝั่งนั้น
  พร้อมชื่อกลุ่มกำกับทุกโต๊ะ (HONDA, เพื่อนเจ้าสาว (ATC), …) → กดโต๊ะเพื่อดูรายชื่อ
  สำหรับผู้ใหญ่ที่พิมพ์ไทยบนมือถือไม่ถนัด หรือคนที่ไม่แน่ใจว่าชื่อตัวเองถูกบันทึกว่าอะไร
- **แผนผัง SVG** ตามแปลนจริง — เวทีอยู่บน ทางเข้าอยู่ล่าง กดโต๊ะดูรายชื่อได้
- **คำบอกทาง** — ไม่ใช่แค่ "โต๊ะ 23" แต่บอกว่าเดินยังไงจากทางเข้า
- **เพื่อนร่วมโต๊ะ** — เห็นว่านั่งกับใคร
- **ทำงานตอนออฟไลน์** — เปิดสำเร็จครั้งเดียวแล้วค้นได้แม้เน็ตหลุด
- **แขกกดนับหัวเอง** — เลือกจำนวน 1-5 คนจากดรอปดาวน์แล้วกด "มาถึงแล้ว" ครั้งเดียว
  ทุกโต๊ะจึงโชว์ว่านั่งไปกี่คนแล้ว · ไม่ต้องใช้รหัส (ดูหัวข้อความปลอดภัยด้านล่าง)
  มีแถวลดจำนวนแยกไว้ให้แก้ถ้ากดพลาด · ดรอปดาวน์ไม่โชว์ตัวเลือกเกินที่นั่งที่เหลือจริง
  *(เลือกทีเดียวเพราะแต่ละครั้งที่ยิงไป Apps Script ใช้เวลา 3-4 วินาที — กดทีละคนคือยืนรอนานกลางงาน)*
- **ปุ่มย้อนกลับทุกหน้า** — ทั้งปุ่มบนเว็บและปุ่ม Back ของมือถือ เพราะทุกหน้ามี URL ของตัวเอง
- **ลิงก์ส่วนตัว** `?g=<id>` — ส่งใน LINE ล่วงหน้า เปิดมาเจอโต๊ะเลย

### หน้าโต๊ะต้อนรับ
- เช็คอินด้วยการกดปุ่มเดียว ไม่มีหน้ายืนยันซ้อน
- สรุปสด: มาแล้วกี่คน · ยังไม่มากี่คน · คิดเป็นกี่ %
- **สถานะโต๊ะ** — เห็นยอดนับหัวที่แขกกดเองคู่กับยอดเช็คอินรายชื่อ
  รู้ทันทีว่าโต๊ะไหนยังว่าง จะได้ย้ายแขกไปโต๊ะสำรอง (19, 20, 39, 40) ได้ทัน
- กดผิดคนกดยกเลิกได้
- รีเฟรชเองทุก 45 วินาที — หลายเครื่องเช็คอินพร้อมกันได้

### หน้าแอดมิน
- เพิ่ม / แก้ / ลบรายชื่อ · ย้ายโต๊ะ
- **นำเข้าชุด** — วางจาก Excel ได้เลย หรือเลือกโต๊ะแล้ววางรายชื่อบรรทัดละคน
- แก้ชื่อกลุ่มของโต๊ะ (ชื่อกลุ่มใช้ค้นหาได้ด้วย)
- เตือนเมื่อโต๊ะคนล้นเกินที่นั่ง และเตือนชื่อซ้ำตอนนำเข้า
- **สร้าง QR** สำหรับพิมพ์ตั้งหน้างาน
- **พิมพ์ป้ายโต๊ะ** (หน้าละโต๊ะ) และรายชื่อทั้งงานให้ทีมงาน
- **ส่งออก CSV** — รายชื่อทั้งหมด และลิงก์ส่วนตัวรายคน
- **แก้/รีเซ็ตยอดนับหัว** — รายโต๊ะหรือทั้งงาน ใช้ตอนทดสอบเสร็จ หรือมีคนกดมั่ว

## ผังโต๊ะ (ตามแปลน VIVACE)

```
            ┌─────── เวที ───────┐
             1  2 │       │ 21 22        ← เลขน้อย = ใกล้เวที
             3  4 │ ทาง   │ 23 24
              …   │ เดิน  │  …
            19 20 │ กลาง  │ 39 40
            └──── ทางขึ้นฮอลล์ ────┘      ← แขกเดินเข้ามาทางนี้

  บล็อกซ้าย = โต๊ะ 1-20 · บล็อกขวา = โต๊ะ 21-40
  ในแต่ละคู่: ซ้ายเลขคู่ / ขวาเลขคี่ = โต๊ะติดทางเดินกลาง
  โต๊ะสำรอง: 19, 20, 39, 40
```

### ⚠️ "ตำแหน่ง" กับ "ฝั่ง" เป็นคนละเรื่องกัน

นี่คือจุดที่พลาดได้ง่ายที่สุดในโปรเจกต์นี้

| | คืออะไร | มาจากไหน | แก้ได้ไหม |
|---|---|---|---|
| **ตำแหน่ง** (block) | โต๊ะตั้งอยู่ซ้าย/ขวาของทางเดินกลาง | คำนวณจากเลขโต๊ะ (`tablePos()`) | ไม่ได้ — ผูกกับแปลนของทางร้าน |
| **ฝั่ง** (side) | เป็นแขกของเจ้าบ่าวหรือเจ้าสาว | คอลัมน์ `Side` ในชีต `Tables` | ได้ — หน้าแอดมิน แท็บ "ตั้งค่าโต๊ะ" |

สองอย่างนี้ **ไม่ตรงกัน** ในงานนี้ — **HONDA (34, 35) และ Thaismile (36-38) ตั้งอยู่บล็อกขวา แต่เป็นแขกฝั่งเจ้าสาว**
ส่วนโต๊ะสำรอง 39-40 ที่อยู่ท้ายบล็อกขวาเป็นของฝั่งเจ้าบ่าว และ 19-20 ท้ายบล็อกซ้ายเป็นของฝั่งเจ้าสาว
รวม 5 โต๊ะที่จะถูกบอกผิดทันทีถ้าใครเผลอไปเดาฝั่งจากเลขโต๊ะ

ผังปัจจุบัน (sync จากชีตจริง 3 ก.ย. 2026): **ฝั่งเจ้าสาว 25 โต๊ะ** = 1-20, 34-38 ·
**ฝั่งเจ้าบ่าว 15 โต๊ะ** = 21-33, 39-40

ในโค้ดจึงบังคับไว้ว่า:
- `tablePos(no)` คืน `block` เท่านั้น — **ไม่มี** field ชื่อ `side` ให้เผลอหยิบไปใช้
- `tableSide(no, tables)` อ่านจากข้อมูลอย่างเดียว ไม่มี fallback ที่เดาให้
- บนแผนผัง **สีของวงกลม = ฝั่ง** ส่วนตำแหน่งซ้าย/ขวา = ที่ตั้งจริง
- `test/search.test.js` มีเคสล็อกไว้ 7 เคส ถ้าใครแก้ให้กลับไปเดาจากเลขโต๊ะ เทสต์จะแดงทันที

ตรรกะตำแหน่งอยู่ใน `tablePos()` ที่ [`js/core.js`](js/core.js) — **ถ้าทางร้านย้ายผัง ต้องแก้ที่นั่นที่เดียว**

## เรื่องความปลอดภัยที่ควรรู้

**รหัสผ่านอยู่ที่เซิร์ฟเวอร์เท่านั้น**
หน้าเว็บทั้งหมดเป็นไฟล์สาธารณะ — โค้ดในนั้นใครก็อ่านได้ รวมถึง `GAS_URL`
การเทียบรหัสฝั่งหน้าเว็บจึงกันอะไรไม่ได้ ด่านจริงอยู่ที่ `checkPin()` ใน `gas/Code.gs`
**ห้ามพิมพ์ `ADMIN_PIN` / `STAFF_PIN` ลงในไฟล์ใด ๆ ในโฟลเดอร์นี้**

**รายชื่อแขกเปิดสาธารณะ**
หน้าแขกต้องค้นหาได้โดยไม่ต้องล็อกอิน และต้องใช้ได้ตอนออฟไลน์
สองข้อนี้แปลว่าข้อมูลทั้งชุดถูกส่งไปที่เครื่องแขกทุกคน
→ **ชื่อ ชื่อเล่น เลขโต๊ะ ของทุกคน ใครที่มีลิงก์ก็ดึงดูได้ทั้งหมด**
จึงจงใจไม่ส่งเบอร์โทรและช่อง "หมายเหตุ" ไปหน้าแขก (อยู่เฉพาะหน้าแอดมิน)
ถ้ารับเรื่องนี้ไม่ได้ ต้องเปลี่ยนไปให้ GAS ค้นหาให้ทีละครั้ง — แลกกับการที่ออฟไลน์จะใช้ไม่ได้

**ปุ่มนับหัวของแขกเปิดให้กดโดยไม่ต้องมีรหัส**
เป็นคำสั่งเดียวใน `gas/Code.gs` ที่ไม่ผ่าน `checkPin()` — เพราะแขกที่เพิ่งเดินเข้างาน
ไม่มีรหัสอะไรทั้งนั้น ถ้าบังคับให้กรอกก็จะไม่มีใครใช้ กันความเสียหายแทนด้วย 4 ชั้น:
1. แตะได้เฉพาะคอลัมน์ `Arrived` — ชื่อกลุ่ม/ฝั่ง/ที่นั่ง แขกแก้ไม่ได้
2. ขยับได้ครั้งละไม่เกิน 5 คน (`MAX_STEP`) ส่งยอดรวมมาเองไม่ได้ — ส่งได้แค่ส่วนต่าง
3. บีบให้อยู่ในช่วง 0 ถึงจำนวนที่นั่ง — ปั่นเป็น 999 ไม่ได้
4. จดลงชีต `Log` ทุกครั้งพร้อมเวลา แอดมินรีเซ็ตได้ใน 5 วินาที

**ยอมรับความเสี่ยงไว้:** คนที่ตั้งใจกวนกด +1 รัว ๆ จนเต็มโต๊ะได้
แลกกับการไม่ต้องให้แขก 400 คนกรอกรหัส — คุ้มกว่าสำหรับงานแต่ง

**ไม่มีอะไรถูกลบจริง**
ลบแขก = จดลงชีต `Log` พร้อม timestamp แล้วค่อยเอาออกจาก `Guests`
ทุกการเพิ่ม/แก้/เช็คอินถูกจดไว้หมด กู้คืนได้เสมอ

## แก้เว็บแล้วต้องทำอะไร

1. แก้ไฟล์ตามปกติ
2. push ขึ้น GitHub Pages

Service worker เป็น **network-first** แล้ว (ตั้งแต่ `seating-v3`) — เครื่องที่เคยเปิดเว็บ
จะได้ไฟล์ใหม่ทันทีในการรีเฟรชครั้งเดียว ไม่ต้องขยับเลขเวอร์ชันทุกครั้งเหมือนเมื่อก่อน
ส่วน cache ถูกลดบทบาทเหลือแค่ "ตัวสำรองตอนเน็ตล่ม" ซึ่งเป็นหน้าที่ที่ควรเป็นตั้งแต่แรก

> **บทเรียนจากของจริง (3 ก.ย. 2026):** เดิมเป็น cache-first ทั้งหมด
> พอแก้ `index.html` กับ `js/core.js` พร้อมกัน เบราว์เซอร์หยิบ HTML เก่ามาคู่กับ JS ใหม่
> หน้าเว็บเลยขึ้น `[object Object]` และปุ่มที่เพิ่งเพิ่มหายไปทั้งหมด
> ปัญหาแบบนี้หาสาเหตุยากมากเพราะไฟล์บนเซิร์ฟเวอร์ถูกต้องทุกอย่าง

**ถ้ายังเห็นของเก่าค้างอยู่** (เกิดกับเครื่องที่เคยเปิดเว็บก่อน `v3` เท่านั้น)
F12 → แท็บ **Application** → **Service Workers** → **Unregister** → รีเฟรช

ยังต้องขยับ `const CACHE` เมื่อเปลี่ยนรายชื่อไฟล์ใน `SHELL` — เพื่อล้าง cache ก้อนเก่าทิ้ง

ถ้าแก้ `gas/Code.gs` ต้อง deploy ใหม่ด้วย — ดูวิธีใน [`gas/README.md`](gas/README.md#แก้โค้ดแล้วต้องทำอะไร)
